# Week 1–3 — History of Computers, Programming, and Computer Basics

## History of Computers

- The history of computing developed from simple calculating devices into programmable electronic computers.
- The **Abacus** was one of the earliest calculating tools.
- **Charles Babbage**
  - Designed the Difference Engine.
  - Designed the Analytical Engine.
  - Often referred to as the **Father of the Computer**.
- **Ada Lovelace**
  - Wrote an algorithm intended for Babbage's Analytical Engine.
  - Recognized as the **first computer programmer**.
- **Herman Hollerith**
  - Developed punched-card tabulating technology.
- **Alan Turing**
  - Developed important theoretical ideas about computation.
  - Associated with the concept of the **Turing Machine**.
- **Atanasoff-Berry Computer (ABC)**
  - An early electronic digital computer.
- **Harvard Mark I**
  - Electromechanical computer.
- **ENIAC**
  - An early programmable general-purpose electronic computer.

---

## Generations of Computers

### First Generation
- Used **vacuum tubes**.
- Computers were very large.
- Used large amounts of electricity.
- Generated significant heat.
- Less reliable than later generations.

### Second Generation
- Used **transistors**.
- Smaller than first-generation computers.
- Faster and more reliable.
- Used less electricity.

### Third Generation
- Used **Integrated Circuits (ICs)**.
- Computers became smaller and cheaper.
- Reliability improved.

### Fourth Generation
- Used **microprocessors**.
- Led to the development and widespread use of personal computers.

### Fifth Generation
- Associated with advanced technologies such as:
  - Artificial Intelligence
  - Machine Learning
  - Advanced computing systems

# Week 3 — Problem Solving

## Problem-Solving Process

The problem-solving process includes:

1. Define the problem.
2. Generate alternative solutions.
3. Evaluate and select an alternative.
4. Implement and follow up on the proposed solution.

---

# Types of Problem Solving

## Trial and Error

- Try different methods until a solution is found.

Example:

A phone is malfunctioning:

1. Restart the phone.
2. Turn Wi-Fi off.
3. Turn Bluetooth off.
4. Continue testing until the cause is found.

---

## Algorithm

- A step-by-step guide or formula for finding a solution.

Examples:

- Following instructions to clear a printer jam.
- Following a mathematical formula.

---

## Heuristic

- Uses mental shortcuts or general problem-solving strategies.
- Can involve breaking a problem into smaller parts.
- Can involve working backwards from the desired result.

---

# Well-Defined Problems

A well-defined problem contains:

1. **Initial State**
   - Where the problem begins.

2. **Goal State**
   - The desired result.

3. **Allowed Operators**
   - The permitted actions or rules used to move toward the solution.

---

# Ill-Defined Problems

- One or more parts of the problem are unclear.
- The starting state, goal, or allowed actions may be vague.

Example:

"Make the program better."

The word "better" has not been clearly defined.

---

# George Polya's Four-Step Problem-Solving Method

1. **Understand the Problem**
2. **Devise a Plan**
3. **Carry Out the Plan**
4. **Look Back**

Example:

The sum of two consecutive integers is 23.

### Step 1 — Understand
Let the numbers be:

x

and:

x + 1

### Step 2 — Devise a Plan

x + (x + 1) = 23

### Step 3 — Carry Out the Plan

2x + 1 = 23

2x = 22

x = 11

The second number is:

12

### Step 4 — Look Back

11 + 12 = 23

The solution is correct.

# Computational Thinking

## What Is Computational Thinking?

Computational thinking is a problem-solving approach in which a problem is formulated so that its solution can eventually be carried out by:

- A computer
- A human
- Another machine

The goal is to produce a solution that can ultimately be programmed into a computer.

---

# Computational Thinking vs. Programming

## Computational Thinking

- Determines **what the solution should do**.
- Focuses on:
  - Logic
  - Organization
  - Problem solving

## Programming

- Converts the solution into instructions that a computer can execute.

Important:

**Computational thinking is NOT the same thing as programming.**

---

# Four Cornerstones of Computational Thinking

## 1. Decomposition

- Break a large problem into smaller and more manageable parts.

Example:

Large Problem

→ Small Problem A  
→ Small Problem B  
→ Small Problem C

---

## 2. Pattern Recognition

- Look for:
  - Similarities
  - Repetition
  - Common patterns

Recognizing patterns can make a solution:

- Simpler
- More manageable
- More efficient

---

## 3. Abstraction

- Focus on important information.
- Ignore unnecessary or irrelevant information.

Important:

**Separating relevant information from irrelevant information is called abstraction.**

---

## 4. Algorithmic Thinking

- Develop a clear step-by-step method for solving the problem.

---

# Computational Problems

## Decision Problem

- Usually has a Yes/No answer.

Example:

Is this number even?

---

## Search Problem

- Requires finding a specific result.

Example:

Find a particular value in a list.

---

## Counting Problem

- Determines the number of possible solutions.

---

## Optimization Problem

- Attempts to find the **best possible solution**.

---

# Five-Step Computational Problem-Solving Method

3. Develop a computational method.
4. Execute the method.
5. Assess the quality of the solution.

# Week 5 — Algorithms

## What Is an Algorithm?

An algorithm is a:

**Clear, unambiguous, step-by-step set of instructions used to solve a problem.**

Important characteristics:

- Step-by-step.
- Language independent.
- Unambiguous.
- Contains predefined instructions.
- Designed before software is developed.
- Efficiency and speed are important considerations.

---

# Search Algorithms

## Linear Search

- Checks elements one at a time.
- Can work with unsorted information.
- Continues until:
  - The value is found.
  - The list ends.

Example:

Find 8:

3, 12, 5, 8, 20

Check 3 → No  
Check 12 → No  
Check 5 → No  
Check 8 → Yes

---

## Binary Search

- Uses a process of elimination.
- Repeatedly divides the remaining search area.
- Requires the list to already be **sorted**.

Basic idea:

1. Check the middle value.
2. Determine which half could contain the target.
3. Eliminate the other half.
4. Repeat.

Important:

**Binary search requires sorted data.**

---

# Sorting Algorithms

## Bubble Sort

- Compares neighboring values.
- Swaps them when they are in the wrong order.
- Repeatedly passes through the data.

---

## Selection Sort

- Finds the smallest value.
- Places it into the correct position.
- Repeats with the remaining values.

---

## Merge Sort

- Uses the **Divide and Conquer** approach.
- Divides data into smaller sections.
- Sorts those sections.
- Merges them together.

---

## Insertion Sort

- Compares values.
- Inserts them into the appropriate position in the sorted portion.

---

# Six Major Types of Algorithms

1. Recursive Algorithm
2. Greedy Algorithm
3. Divide and Conquer Algorithm
4. Brute Force Algorithm
5. Dynamic Programming Algorithm
6. Backtracking Algorithm

---

# Recursive Algorithm

- Breaks a problem into smaller versions of itself.
- Repeats until a solution is found.
- Often uses more computational resources and memory.

Examples:

- Tower of Hanoi
- Graph-search problems

---

# Greedy Algorithm

- Attempts to find an optimal solution.
- Makes the best available choice at each step.
- Uses a set of rules.

Applications include:

- Dijkstra's Algorithm
- Huffman Encoding

A greedy algorithm may fail to find the globally optimal solution when information is incomplete.

---

# Divide and Conquer

The problem is divided into smaller independent problems.

Three main steps:

1. Divide the problem.
2. Solve the smaller problems.
3. Merge the solutions.

Examples:

- Binary Search
- Merge Sort

---

# Brute Force Algorithm

- Straightforward approach.
- Tries possibilities until a solution is found.
- Does not normally use advanced shortcuts.
- Can require more:
  - Time
  - Memory

---

# Dynamic Programming

- Uses previously calculated information.
- Avoids repeating work.
- Improves efficiency.
- Useful when problems contain:
  - Overlapping subproblems.
  - Optimal substructures.

---

# Backtracking

- Solves problems incrementally.
- Rejects solutions that fail to satisfy constraints.
- Returns to an earlier point and tries another possibility.

Examples:

- Sudoku
- N-Queens

---

# Algorithm Development Process

1. Obtain the problem description.
2. Analyze the problem.
3. Develop a high-level algorithm.
4. Refine the algorithm.
5. Review the solution.

---

# Runtime Analysis

Runtime analysis helps determine algorithm efficiency.

## Omega — Ω

- Represents a lower bound.
- Associated in the course material with the **best case**.

## Theta — Θ

- Represents asymptotic or tight behavior.

## Big-O — O

- Represents an upper bound.
- Associated in the course material with the **worst case**.

---

# Week 5 — Flowcharts

## What Is a Flowchart?

A flowchart is a:

**Step-by-step visual representation of a process or algorithm.**

Flowcharts are used to:

- Plan programs.
- Represent algorithms.
- Visualize logic.
- Identify errors before coding.
- Communicate processes.

---

# Important Flowchart Symbols

## Start / End

Shape:

**Rounded terminator / oval**

Purpose:

- Shows the beginning or ending of an algorithm.

---

## Process

Shape:

**Rectangle**

Purpose:

- Represents an action or processing step.

Example:

total = A + B

---

## Input / Output

Shape:

**Parallelogram**

Purpose:

- Input from the user.
- Output produced by the program.

Examples:

Input age

Display total

---

## Decision

Shape:

**Diamond**

Purpose:

- Represents a condition or decision.

Usually branches into:

- Yes / No
- True / False

---

## Flow Line

Shape:

**Arrow**

Purpose:

- Shows the sequence of instructions.
- Shows the direction of control flow.

---

## Connector

- Shows that the flow continues in another location.

---

# Rules for Good Flowcharts

- Use one Start.
- Every path should eventually reach an End.
- Flow usually moves:
  - Top to bottom.
  - Left to right.
- Decision symbols should have clearly identified exits.
- Decision exits are commonly labeled:
  - Yes
  - No
- Keep text inside symbols short.
- Test the flowchart using sample information.
- Revise the flowchart if errors are found.

---

# Three Main Programming Structures

## 1. Sequence

Instructions execute one after another.

Example:

Start

↓

Input A

↓

Input B

↓

Sum = A + B

↓

Output Sum

↓

End

---

## 2. Selection

A decision determines which path is followed.

Example:

mark >= 50?

Yes → Output "Pass"

No → Output "Fail"

---

## 3. Repetition

Instructions repeat while a condition applies.

Example:

n = 1

↓

Is n <= 5?

Yes:

Display n

n = n + 1

Return to condition

No:

End

---

# Flowchart Decision Statements

## IF Statement

- Performs instructions when a condition is true.

---

## IF-ELSE Statement

- One action occurs when the condition is true.
- Another action occurs when the condition is false.

---

## SWITCH / CASE Statement

- Used for multiple possible decisions.
- Also called a **multi-way decision statement**.

# Week 6 — Pseudocode

## What Is Pseudocode?

Pseudocode is an:

**Informal representation of actual computer code.**

It is used as a rough draft or outline of a program.

Important characteristics:

- No predefined strict syntax.
- Written in simple language.
- Helps organize ideas before coding.
- Allows programmers to concentrate on logic instead of programming-language syntax.
- Can communicate an algorithm across different programming languages.

---

# Algorithm vs. Pseudocode

## Algorithm

- Defines the step-by-step procedure used to solve a problem.

Example:

1. Get hours worked.
2. Get hourly pay rate.
3. Multiply hours by pay rate.
4. Display the result.

---

## Pseudocode

Represents the algorithm in a human-readable, program-like format.

Example:

DISPLAY "Enter number of hours"

INPUT hours

DISPLAY "Enter hourly pay rate"

INPUT payRate

SET grossPay = hours * payRate

DISPLAY grossPay

Important:

**Pseudocode is NOT a computer program.**

It represents the algorithm in simplified natural language.

---

# How to Write Pseudocode

- Arrange tasks in the correct sequence.
- Define the main goal of the program.
- Indent:
  - IF-ELSE statements.
  - FOR loops.
  - WHILE loops.
  - Nested structures.
- Follow clear naming conventions.
- Keep variables and names understandable.
- Avoid making the pseudocode too abstract.
- Avoid unnecessary technical jargon.
- Use programming-style control words when appropriate.
- Review the pseudocode after writing it.
- Make sure every section is complete and understandable.

---

## Input Keywords

- OBTAIN

## Output Keywords

- SHOW

- DISPLAY

## Processing Keywords

- DETERMINE

## Initialization

## Incrementing

---

# Six Structured Programming Constructs in Pseudocode

1. SEQUENCE
2. IF-THEN-ELSE
3. FOR
4. WHILE
5. REPEAT-UNTIL
6. CASE

---

# SEQUENCE

- Instructions execute from top to bottom.
- One action follows another.
- Instructions at the same level use the same indentation.

Example:

READ length

READ width

COMPUTE area = length * width

DISPLAY area

---

# IF-THEN-ELSE

Used for a **binary choice involving a Boolean condition**.

Example:

IF mark >= 50 THEN
    DISPLAY "Pass"
ELSE
    DISPLAY "Fail"
END IF

---

# FOR Loop

- Used when something repeats a specific number of times.
- Often called a **counting loop**.

General form:

FOR iteration limits
    sequence
ENDFOR

Example:

FOR i = 1 TO 10
    DISPLAY i
ENDFOR

---

# WHILE Loop

- The condition appears at the **top** of the loop.
- The condition is tested before the instructions inside the loop execute.

General form:

WHILE condition
    sequence
ENDWHILE

Important:

**WHILE = test first, execute afterward.**

---

# REPEAT-UNTIL Loop

- Similar to a WHILE loop.
- The condition is tested at the **end** of the loop.

General form:

REPEAT
    sequence
UNTIL condition

Important:

**REPEAT-UNTIL = execute first, test afterward.**

---

# WHILE vs. REPEAT-UNTIL

| WHILE | REPEAT-UNTIL |
|---|---|
| Condition tested at the top | Condition tested at the bottom |
| Tests before executing | Tests after executing |
| May execute zero times | Body executes before the condition is checked |

---

# CASE

- Represents a **multiway branch**.
- Used when several mutually exclusive choices are possible.

General form:

CASE expression OF
    condition1:
        sequence1
    condition2:
        sequence2
    condition3:
        sequence3
ENDCASE

---

# Nested Constructs

A nested construct occurs when one programming structure is placed inside another.

Example:

SET total = 0

REPEAT
    READ temperature

    IF temperature > freezing THEN
        INCREMENT total
    END IF

UNTIL temperature < 0

PRINT total

In this example:

- The IF statement is **nested inside** the REPEAT loop.

Important:

- Nested structures must be properly **indented**.

---

# Flowcharts vs. Pseudocode

Flowcharts and pseudocode can represent the **same algorithm**.

The difference is how the logic is displayed.

## Flowchart

Uses:

- Shapes
- Arrows

## Pseudocode

Uses:

- Written instructions
- Keywords
- Indentation

Example pseudocode:

READ mark

    DISPLAY "Pass"
ELSE
    DISPLAY "Fail"
END IF

Both representations describe the same logical solution.

# Important Differences to Know

## Computational Thinking vs. Programming

Computational Thinking:

- Develops the logical solution.

Programming:

- Implements the logical solution using code.

---

## Algorithm vs. Pseudocode

Algorithm:

- Defines the step-by-step solution.

Pseudocode:

- Represents that solution in a human-readable, program-like format.

---

## Algorithm vs. Trial and Error

Algorithm:

- Uses predetermined steps or a formula.

Trial and Error:

- Tries different possibilities until something works.

Example:

Using the quadratic formula is an **algorithmic approach**, not trial and error.

---

## WHILE vs. REPEAT-UNTIL

WHILE:

Test condition first.

REPEAT-UNTIL:

Execute instructions first, then test the condition.

---

## Decision vs. Process in a Flowchart

Decision:

Diamond

Process:

Rectangle

---

## Selection vs. Repetition

Selection:

Choose one path based on a condition.

Repetition:

Repeat instructions while or until a condition is satisfied.
